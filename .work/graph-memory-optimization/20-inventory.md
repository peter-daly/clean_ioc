# Task 20 — Validation ownership and source/check matrix

Date: 2026-10-10\
Status: Implemented for task 20; scoped coordinator review accepted\
Contract: [19-contract.md](19-contract.md), including the accepted one-attempt builder lifecycle and ordinary-reference Composition ownership.

This matrix describes the implemented policy boundary. **A** is analysis-only checking; **W** is shared selection/instruction computation; **I** is input admission or an actual runtime guard. These are classifications of source responsibilities, not selectable modes or rule categories. `build()` does not run custom rules, built-in policy passes, or safety audits. `analyse()` uses the shared emitter and completes available checks before returning its report.

Exact source identity, every changed-file before/after hash, and the supporting package hashes are in [final-source-manifest.json](evidence/20/final-source-manifest.json). [source-symbols.json](evidence/20/source-symbols.json) records line locations for these exact bytes. The [task-relative patch](evidence/20/task20.patch) is against the preserved dirty pre-task source, **not** against HEAD.

## Explicit remaining implementation boundaries

- **Task 21:** replace the temporary minimal `CompiledGraph` support branch with execution-only finalization; release consumed-builder declarations; project analysis execution plans without retaining graph/blueprint owners; give each created root runtime independent preconfiguration state. Preserve execution emission independently when inspection-only architecture roots fail.
- **Task 22:** remove remaining diagnostic/census/origin/callback-evidence allocation from the build pipeline. This task removed policy work and the rule-triggered rich fallback; it does not claim the complete zero-allocation contract.
- **Task 23:** external structurally immutable Composition capture/parent matching, ordinary scope creation and inherited composition, warmup/observation descriptors without graph/manifest readers. `AnalysisResult.composition` is currently absent. There is no new Composition close/aclose/context-manager lifecycle.
- **Task 24:** migrate remaining runtime graph/report convenience APIs, non-check CLI commands, docs, old mode/private-harness tests, and full consumers. `BuildReport` is a temporary alias of the new immutable [AnalysisReport](../../clean_ioc/tooling.py#L510), with no replay behavior. Remaining tooling loaders still contain obsolete mode calls and are not release-ready.
- **Task 25:** final native/Linux startup, timing, traced/untraced memory and consumer acceptance after tasks 20–24 integrate. The maintainer deferred further measurements; no performance saving or full-upgrade attribution is claimed here.

These boundaries are implementation work, not hidden validation compatibility. Old tests expecting production rejection or a second validation pass must migrate rather than restoring either behavior.
