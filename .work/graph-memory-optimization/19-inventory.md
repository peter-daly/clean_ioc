# Task 19 — Source-backed check and ownership inventory

Date: 2026-10-10\
Status: Reviewed classifications for the task 19 implementation plan\
Source: working-tree [container.py](../../clean_ioc/container.py), SHA-256
`1a60386b392058ac47143b3acf4fc82b1034b95f360854dae2e98ff6cde42223`.
Line numbers below refer to those exact bytes, not the eventual implementation.

Read with the [contract](19-contract.md). **A** means analysis-only proof/audit;
**W** means a computation needed to select or emit a declared instruction;
**I** means input representation, operation admission, or actual runtime state.
Mixed rows deliberately split checks inside one existing helper. W failures are
local emission errors only when a concrete instruction/identity cannot be produced;
they are not a retained whole-graph validation pass. I never means moving an
architectural rule into declaration parsing to keep rejecting it before build.

## Required acceptance coverage for implementation tasks

The contract's error/example table is normative for the reviewed plan. Task 20 must
turn the mixed rows into focused tests for both ordinary and generated/private/
deferred paths, including rejected and unused declarations. Task 21 verifies the
same valid wiring without report finalization. Task 22 verifies absent evidence
allocation from declaration through finalization, including rules registered but
never invoked. Task 23 verifies warmup/instrumentation/overlay ownership without
inspection graphs. Task 24 changes tooling and consumer expectations together.
Task 25 measures the whole consumer upgrade. None is assigned or implemented by
this inventory, and no memory saving is claimed from a source classification.
